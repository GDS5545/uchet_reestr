ZAU Профсоюз 2.28.0 — точный перенос 1:1 со старого сайта
(Ultimate Member + WPForms) и исправление чужих данных в кабинете

ПОЧЕМУ ПРЕЖНИЕ ПЕРЕНОСЫ ПЕРЕПУТАЛИ ДАННЫЕ
-----------------------------------------
1. Профиль собирался из ВСЕХ заявлений, прикреплённых к старому аккаунту.
   Если с одного аккаунта подавали заявления за других (председатель
   профкома, ответственный, родственник), в профиль владельца попадали
   чужие ФИО, ИИН и организация (class-zau-remote-smart-dedup.php,
   merge_profile()).
2. Люди «угадывались» по ФИО, email, телефону и ИИН
   (class-zau-universal-import.php, find_user()); PDF привязывались по любым
   числам в имени файла, которые могли совпасть с чужим ID.
3. Для каждого вида заявления оставлялась только «самая новая», остальные
   уходили в архив переноса — в кабинете часть заявлений пропадала.
4. Если в карточке поле пустое, она подставляла данные из последней заявки
   аккаунта — в том числе из заявки, поданной за другого человека.

ЧТО СДЕЛАНО
-----------
Новый раздел «Импорт и перенос → Точный перенос 1:1» и новый мост для
старого сайта (old-site-bridge/zau-legacy-exact-export.php). Правила:

 - Один старый аккаунт = один аккаунт нового сайта. Связь только по старому
   User ID; существующий аккаунт используется лишь при ТОЧНОМ совпадении
   email. Никаких объединений по ФИО, телефону или ИИН.
 - Профиль заполняется из самого аккаунта Ultimate Member (имя, фамилия,
   телефон, анкета регистрации). Из заявлений — только пустые поля и только
   если ФИО в заявлении совпадает с владельцем аккаунта. Данные, введённые
   на новом сайте, не перезаписываются.
 - КАЖДАЯ запись WPForms переносится отдельной архивной заявкой, ничего не
   объединяется и не отбрасывается. Заявка, поданная с аккаунта за другого
   человека, остаётся у подавшего с пометкой «подано за другого человека» и
   не влияет на его профиль. Спам/корзина WPForms сохраняются, но в кабинете
   не показываются.
 - Файлы из заявлений (подписи, вложения) скачиваются со старого сайта.
 - Каждая запись хранит исходную копию и контрольную сумму SHA-256.
   «Сверка 100%» сравнивает копии с живыми данными старого сайта и
   показывает, что перенесено всё и без искажений (или что именно не так).
 - Перенос можно запускать повторно: перенесённое не дублируется,
   изменённое на старом сайте обновляется, решения пользователей и
   администратора сохраняются.
 - «Скрыть дубли прежних переносов»: заявки, созданные старыми
   инструментами, для которых есть точная копия, получают статус
   «заменена точной копией», их PDF переходят к правильному владельцу.
   Ничего не удаляется; есть кнопка «Откатить скрытие».

В ЛИЧНОМ КАБИНЕТЕ (вкладка «Заявления»)
 - Блок «Заявления со старого сайта» — все старые заявления с полями.
 - «Пересоздать заявление» открывает форму, заполненную данными старого
   заявления; после отправки создаётся новое заявление, старое остаётся.
 - «Это не моё заявление» — заявление убирается из профиля и попадает
   администратору. Для заявлений «за другого человека» — «Это моё
   заявление».
 - «В профиле чужие данные» (также в личной карточке) — сообщение
   администратору.

ОЧЕРЕДЬ АДМИНИСТРАТОРА (внизу страницы «Точный перенос 1:1»)
 - «Пользователь отметил „не моё“» — передать заявку владельцу (ID, email
   или логин), оставить владельцу, пометить как поданную за другого.
 - «Профили на проверку» — жалобы пользователей и аккаунты, которые прежний
   перенос связывал с другим старым пользователем. «Пересобрать профиль»
   заменяет ФИО, телефон, ИИН, организацию и карточку данными только из
   старого аккаунта и собственных заявлений; «Вернуть как было» отменяет.
 - «Без владельца» — записи гостей без аккаунта и администраторов старого
   сайта; назначьте владельца вручную.
 - «Поданы за другого человека» — при желании передайте заявку аккаунту
   самого заявителя.

ПОРЯДОК ДЕЙСТВИЙ
----------------
1. Резервная копия базы и wp-content/uploads нового сайта.
2. СТАРЫЙ сайт (uchet.zdravunion.kz): загрузите
   old-site-bridge/zau-legacy-exact-export.php как отдельный плагин
   (Плагины → Добавить → Загрузить, предварительно упаковав файл в zip),
   активируйте. Инструменты → ZAU точный экспорт → «Разрешить выгрузку»,
   сохраните, скопируйте ключ. Мост только читает данные.
3. НОВЫЙ сайт (new.zdravunion.kz): Импорт и перенос → Точный перенос 1:1 →
   адрес старого сайта и ключ → «Проверить подключение».
4. «Пробный перенос» → скачайте отчёт. Строки conflict, unassigned и
   other_person просмотрите.
5. «Перенести».
6. «Сверка 100%» — должна показать зелёное «100%». Если есть расхождения,
   повторите «Перенести» и сверку.
7. «Проверить» → «Скрыть дубли прежних переносов».
8. Разберите очередь «Профили на проверку».
9. Прежние инструменты («Перенос со старого сайта», «Перенос старых
   данных (WPForms)») больше не запускайте.

Обновление добавляет таблицы wp_zau_exact_map и wp_zau_exact_report.
Существующие таблицы не меняются.
