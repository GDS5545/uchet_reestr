Мост-компаньон (старый сайт) 1.0.0 -> 1.1.0 — исправлена остановка переноса
на больших объёмах данных

Симптом: при переносе аккаунтов/заявлений по API прогресс застревал на
каком-то числе (например, 7100) и не шёл дальше, при этом в логе было
"Сервер остановил перенос по API: HTTP 200".

Причина: методы /users и /entries на старом сайте отдавали страницы через
OFFSET (пропустить N записей, взять следующие). При росте OFFSET MySQL
приходится каждый раз заново сканировать и отбрасывать всё больше уже
отданных строк — на достаточно большом смещении это стало медленнее
таймаута выполнения PHP на старом сайте. Сервер в этот момент успевал
начать ответ (отсюда HTTP 200), но обрывал его на середине — тело
переставало быть валидным JSON, и перенос падал с ошибкой разбора ответа.

Исправление: обе точки теперь читают страницы курсором по первичному
ключу (WHERE ID > курсор ORDER BY ID LIMIT ...) вместо OFFSET. Скорость
чтения каждой страницы теперь не зависит от того, как далеко продвинулся
перенос — так же быстро на записи №100, №7100 и №17000.
