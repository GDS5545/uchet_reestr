ZAU Профсоюз 2.19.0 — один инструмент переноса вместо пяти

Пять прежних инструментов переноса удалены и заменены одним:
Профсоюз → Перенос со старого сайта.

Удалено:
- Импорт аккаунтов (универсальный CSV-импорт).
- Перенос старого сайта (защищённый мост + отдельный плагин-экспортёр).
- Быстрая проверка дублей (умная дедупликация).
- Исправить профили.
- Перенос старых данных (прямой перенос из wpforms_entries на том же сайте).

Почему: эти инструменты дублировали друг друга и часть из них сопоставляла
людей нечётко — по совпадению ФИО, email, телефона или ИИН. При наличии
однофамильцев или общих корпоративных email/телефонов это требовало
постоянной ручной проверки и не давало гарантии, что заявление попадёт
к нужному человеку.

Новый принцип: только точные старые ID
----------------------------------------
На старом сайте (Ultimate Member + форма заявления) каждому пользователю и
каждой записи заявления соответствует свой числовой ID. Этот же ID стоит в
конце имени файла PDF заявления и личной карточки. Новый инструмент
сопоставляет данные ТОЛЬКО по этому точному ID — без угадывания по имени.
Перенос можно запускать повторно: строки и файлы, которые уже перенесены,
не задваиваются.

Порядок переноса
-----------------
1. Сделайте резервную копию базы данных нового сайта.
2. Со старого сайта выгрузите пользователей Ultimate Member в CSV. Обязательно
   включите колонку с ID пользователя.
3. Профсоюз → Перенос со старого сайта → шаг 1 «Аккаунты» → загрузите CSV,
   сопоставьте колонку с ID пользователя Ultimate Member (обязательно) и
   остальные поля, запустите сначала «Только проверить», затем перенос.
4. Со старого сайта выгрузите записи формы заявления в CSV. Обязательно
   включите ID записи и ID пользователя-владельца (тот же ID, что и в п.2).
5. Шаг 2 «Заявления» → выберите форму нового кабинета, к которой привязать
   перенесённые заявления, → загрузите CSV → перенос. Заявления без ранее
   перенесённого владельца попадут в отчёт как «пропущено» — сначала
   довезите соответствующие аккаунты.
6. Скопируйте PDF заявлений и личных карточек по FTP/SFTP в папку
   wp-content/uploads/zau-legacy-pdfs/ (имя папки можно изменить).
7. Шаг 3 «Привязка PDF» → укажите, по какому фрагменту имени файла и по
   какому регулярному выражению искать ID для личной карточки и для
   заявления, выберите PDF-шаблон каждого типа → «Просканировать папку» →
   проверьте, что ID найдены и есть куда их привязать → «Привязать
   найденные PDF». Успешно привязанные файлы переносятся в подпапку
   «обработано» внутри той же папки — исходники не удаляются.

Что осталось от старых инструментов
------------------------------------
Логика сопоставления телефона/даты, привязки организации по БИН и филиала
по названию перенесена в новый инструмент без изменений. CSV-отчёт по
каждому шагу по-прежнему доступен для скачивания.
