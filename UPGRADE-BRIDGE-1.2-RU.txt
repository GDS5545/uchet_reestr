Мост-компаньон (старый сайт) 1.0.0 -> 1.2.0 — исправлена остановка переноса
на больших объёмах данных

Симптом: при переносе аккаунтов/заявлений по API прогресс застревал на
каком-то числе (например, 7100) и не шёл дальше, при этом в логе было
"Сервер остановил перенос по API: HTTP 200".

Причина: методы /users и /entries на старом сайте отдавали страницы через
OFFSET (пропустить N записей, взять следующие). При росте OFFSET MySQL
приходится каждый раз заново сканировать и отбрасывать всё больше уже
отданных строк — на достаточно большом смещении это стало медленнее
таймаута выполнения PHP на старом сайте. Сервер в этот момент успевал
начать ответ (отсюда HTTP 200), но обрывал его на середине — тело
переставало быть валидным JSON, и перенос падал с ошибкой разбора ответа.

Исправление (1.1.0): обе точки теперь читают страницы курсором по
первичному ключу (WHERE ID > курсор ORDER BY ID LIMIT ...) вместо OFFSET.
Скорость чтения каждой страницы теперь не зависит от того, как далеко
продвинулся перенос — так же быстро на записи №100, №7100 и №17000.

Если после этого перенос всё равно останавливался на ТОЙ ЖЕ самой цифре
(например, снова ровно на 7100) — значит дело было не в скорости, а в
одной конкретной "битой" записи (пользователе или заявлении), на которой
сервер падал с ошибкой независимо от способа постраничного чтения — та же
запись оказывалась на той же позиции что при OFFSET, что при курсоре.

Исправление (1.2.0): каждая запись теперь обрабатывается отдельно, в
try/catch. Если на одном пользователе/заявлении происходит ошибка, вся
страница больше не обрывается — эта запись помечается как ошибочная
(с текстом ошибки) и пропускается, перенос идёт дальше. Ошибочные записи
будут видны в логе переноса на новом сайте. Дополнительно каждая страница
ограничена 15 секундами: если сервер медленный по любой другой причине,
плагин вернёт то, что успел собрать, с корректным курсором для
продолжения, а не оборванный ответ.
