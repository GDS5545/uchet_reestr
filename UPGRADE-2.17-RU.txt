ZAU Профсоюз 2.17.0 — безопасное объединение дублей и выбор последней заявки

Главное изменение
-----------------
Перенос через старый сайт больше не создаёт аккаунт по каждой строке заявления.
Сначала все исходные аккаунты и заявления помещаются в отдельную таблицу анализа,
затем система группирует одного человека и выбирает последнюю уникальную заявку.

Правила определения человека
-----------------------------
1. ИИН — самое сильное совпадение.
2. Email.
3. Телефон после нормализации форматов +7/8/скобки/пробелы.
4. Связь со старым WordPress User ID.
5. ФИО + дата рождения.
6. ФИО + организация/филиал.
7. Одно ФИО без других признаков по умолчанию НЕ объединяется и не импортируется:
   запись получает решение review_required.

Защита от опасных объединений
-----------------------------
- Разные ИИН внутри одной предполагаемой группы блокируют импорт группы.
- Один email или телефон с разными ФИО без подтверждающего ИИН отправляется на проверку.
- Полные повторы содержимого заявления получают решение exact_duplicate.
- Записи, уже перенесённые ранее, получают решение already_imported.
- Повторный запуск не создаёт точные дубли.

Выбор последней заявки
----------------------
Для каждого человека и каждого семейства форм выбирается одна новая уникальная заявка.
Формы о вступлении, удержании/уплате взносов и регистрации распознаются по названию,
даже если на старом сайте менялся ID формы.

Сравнение:
1. дата подачи заявления;
2. при одинаковой или отсутствующей дате — больший старый Entry ID;
3. при полном совпадении данных более старая запись отмечается exact_duplicate.

По умолчанию в новый кабинет переносится только последняя заявка каждого вида.
Старые строки не удаляются: они остаются в таблице архива миграции и в отчёте,
а их старые Entry ID связываются с тем же новым аккаунтом для последующей привязки PDF.

Данные профиля
--------------
Личная карточка собирается из всех надёжно связанных записей. Для каждого непустого
поля используется наиболее новое значение. При этом без отдельной галочки плагин
не заменяет данные, которые уже были введены на новом сайте вручную.

Пробный анализ
--------------
Пробный анализ теперь считает уникальных людей, а не строки. Он ничего не создаёт.
Полный отчёт больше не обрезается на 3000 строк. ИИН, телефон и email в отчёте
маскируются.

Перед запуском
--------------
1. На старом сайте обновите мост экспорта до версии 1.1.0.
2. На новом сайте установите ZAU 2.17.0.
3. Сделайте резервные копии обеих баз и uploads.
4. Запустите полный пробный анализ.
5. Проверьте review_required и identity_conflict.
6. Только затем запускайте настоящий перенос.
